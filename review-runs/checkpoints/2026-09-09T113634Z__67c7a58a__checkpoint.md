### P2-B — NEW: ordinary History commit can be followed by producer replay after process death

For a non-replacement Download, ordinary History persistence occurs before `DownloadRepository.completeAndDelete()`. A crash between those durable effects leaves an Active/PostProcessing Download row without the dedicated `HISTORY_FINALIZATION` carrier used for committed History replacements. Startup recovery can therefore requeue the row, and the next attempt adopts any prior publication destinations but still enters `executeYtdlpPhase()`. The already durable ordinary success sink is not a producer-suppressing semantic-success witness.

### P2-C — NEW: committed provider destination can be recreated after source-retirement failure

MediaStore publication can be finalized and durably journaled before local source deletion. If source deletion fails, `DownloadWorker` retries that remaining source. `PublicationRecoveryJournal.reserveIntent()` returns success when the same source already has a committed `destinationPath`, so the new move invocation may call the provider create/insert path again. MediaStore unique-name selection can create a collision-suffixed second row. A later destination reservation conflicts with the already committed first URI and depends on successful deletion of the accidental second provider object; if deletion is not acknowledged, both may survive. Even when cleanup succeeds, the committed first publication is incorrectly re-entered as failure/retry work instead of leaving only source-retirement debt.
