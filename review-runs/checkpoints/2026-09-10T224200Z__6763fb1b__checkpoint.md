## New P2 subfinding
### `BUG-LOCALADD-01 / provider-local documentId collision`
Current `LocalAddWorker` computes `dedupedEntries = entries.distinctBy(localEntryIdentity)`. For non-tree entries where `DocumentsContract.getDocumentId(uri)` succeeds, `localEntryIdentity()` returns only `doc:<documentId>` and omits the content-provider authority. Android defines a document ID as unique within a provider, not globally. Therefore two valid URIs such as `content://provider.a/document/42` and `content://provider.b/document/42` can map to the same implemented identity `doc:42`; `distinctBy` silently drops the later sibling before the worker reaches its exact URI/tree/path checks.

- severity: P2
- disposition: NEW subfinding / OPEN under existing `BUG-LOCALADD-01`
- violated invariants: destructive/durable identity granularity and provenance; sibling isolation; candidate rejection only after the invariant disproves it.
- production path: LocalAdd input entries -> `distinctBy(localEntryIdentity)` -> provider-local documentId fallback -> later sibling omitted -> no History/pending representation for the omitted entry.
- affected production file: `app/src/main/java/com/ireum/ytdl/work/LocalAddWorker.kt`
- concrete evidence: authority is absent from `return "doc:$documentId"`; dedupe executes before all later per-entry exact URI/tree/path checks.
