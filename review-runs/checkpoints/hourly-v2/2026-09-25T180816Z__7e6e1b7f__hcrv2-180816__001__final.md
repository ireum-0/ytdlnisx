## Findings

### Existing P2 — BUG-DUPLICATE-03 remains OPEN

The main SAF-authority correction is materially present:

- configured archive authority is typed as `RawFile`, `SafTree`, or `Unresolved`;
- provider-backed configuration retains the exact `content://` tree instead of reconstructing a raw path;
- queue and Observe distinguish `Available` from `Unavailable` and fail closed on unreadable authority;
- native yt-dlp receives the app-owned generation-private archive when present and does not synthesize a provider pathname;
- generation-private archive promotion re-reads the configured authority before retiring private evidence;
- promotion failure leaves exact private-generation/finalization recovery evidence.

The remaining correctness gap is at the provider destructive-replacement boundary.

Production `SafDownloadArchiveProvider.replaceText()` opens the authoritative archive with:

`contentResolver.openOutputStream(target.uri, "wt")`

and then writes/flushes directly into that authoritative document.

Android `ContentResolver` defines `wt` as write-and-truncate, and provider implementations may differ in exact stream behavior. The operation is not an application-level atomic replacement guarantee. A write/flush/close failure after truncation or partial mutation may therefore leave a readable but incomplete configured archive.

`DownloadArchiveAuthority.promote()` correctly retains the private generation when replacement/verification fails, and worker/recovery paths retain primary-success finalization debt. However ordinary queue and Observe preflights call `ConfiguredDownloadArchiveStore.read()` directly and do not consult a durable provider-promotion fence or the pending finalization authority before accepting a successful read as complete membership.

Concrete same-root failure:

1. configured provider archive contains A + B;
2. generation-private archive contains A + B + C;
3. primary media success is durable;
4. provider replacement truncates/mutates the configured archive;
5. only A is present when write/flush/close fails;
6. private generation/finalization debt survives;
7. configured provider document is nevertheless readable as A;
8. queue/Observe classify that read as `Available([A])`;
9. B is treated as absent and may be admitted again before recovery restores the archive.

The existing production-wiring failure test does not close this row: its fake throws `writeFailure` before mutating `contents`.

### Additional same-root concurrency subcase

The same missing fence also leaves a concurrent authority window even without a terminal provider exception: queue/Observe reads do not participate in `DownloadArchiveAuthority.promotionLock` and have no durable admission fence. A provider implementation that exposes readable intermediate content during replacement can therefore allow duplicate preflight to observe incomplete membership while promotion is in progress.

This is a subcase of `BUG-DUPLICATE-03`, not a new root.

Historical code named `download_archive_path` as a folder and appended `download_archive.txt`. This run did not establish whether any supported upgrade/restore path can still contain such a legacy absolute folder value. Keep this compatibility cell `NOT_VERIFIED`; do not reclassify it as a defect without migration/provenance evidence.
