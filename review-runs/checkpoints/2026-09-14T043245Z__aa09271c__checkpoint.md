## Open findings / candidates
### Existing F20 / BUG-LOCALADD-01 — P2 OPEN
The latest remediation is incomplete. Same-provider metadata is treated as sufficient tree authority. `buildTreeMeta` and `relativePath` derive a relative path by interpreting opaque provider document IDs with string `removePrefix`. Android specifies `COLUMN_DOCUMENT_ID` as provider-defined opaque identity. Same authority does not prove descendant membership; `DocumentsContract.isChildDocument` exists for that semantic question.

Concrete false-positive dedupe:
1. tree URI has authority `provider` and tree document ID `root`;
2. distinct unrelated file A in the same provider has document ID `other` but stale/mismatched tree metadata `tree=root`;
3. current code derives/stores relative `other` and identity `tree:<root>|other`;
4. genuine descendant file B has document ID `root/other` and correctly derives the same tree identity;
5. final `insertLocalHistory` sees equal storage identity and silently returns AlreadyPresent for one distinct local file.
This violates F20: filename stem alone never discards a local file and same-name/identity ambiguity must fail open rather than silently discard a distinct file. Runtime reproduction in this review: NOT_VERIFIED.
