## Open findings / questions

### NEW P1 — CLEANUP-MAIN-THREAD-BLOCK-01

Production `DownloadSettingsFragment` invokes `CleanupScheduleCoordinator.configure()` synchronously from the preference-change listener. `configure()` uses `runBlocking` and may wait on `destructiveEffectMutex`, while a background cleanup worker can hold that mutex across database deletion and cache deletion. Therefore changing the setting during a sufficiently long cleanup can block the Android main thread for the cleanup duration and reach ANR-class unresponsiveness.

Runtime manifestation is NOT_VERIFIED; the source path and blocking dependency are confirmed.

## Exact upstream semantic basis

- Kotlin `Mutex.withLock`: competing callers suspend while the mutex is held; the protected action is executed under the mutex.
- Android ANR guidance: input-dispatch timeout is normally about five seconds; main-thread blocking and lock contention are explicit ANR causes, and long/blocking work must be moved off the main thread.
- Android DocumentsProvider contract: provider document IDs are provider-defined opaque identifiers, so clients must not derive path semantics from lexical prefixes.
- Repository v6: semantic-contract deltas require full consumer/authority-effect closure; discovery is not final mutation authority; identity claims preserve granularity/provenance; CLEAN requires semantic closure plus required actual execution evidence.
- Master Plan F10 and F20 invariants at frozen Plan SHA.

## Checklist evolution candidate

Checklist gap: v6 requires consumer closure and concurrency review, but does not explicitly force thread-affinity/blocking classification when a new mutex/lease is held across suspending or slow I/O and then reached from synchronous UI consumers.

Proposed checklist change: for every newly introduced or widened mutex/lease that spans suspension, DB/filesystem/network/native I/O, enumerate every synchronous caller and its thread affinity. If a UI/main-thread caller can wait on that lease, require an asynchronous/bounded handoff or an explicit proof the wait cannot approach the platform ANR threshold. Add a deterministic production-wiring test that holds the worker lease and invokes the real UI consumer without blocking the main dispatcher.
