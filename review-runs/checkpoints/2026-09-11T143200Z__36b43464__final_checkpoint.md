## Final open finding
### `BUG-METADATA-02 / fragment-blind generic fresh source validation`
- severity: P2
- status: NEW subfinding / OPEN / existing canonical root
- violated invariant: Master Plan F13, unrelated fresh metadata contributes no field to a Download row.

Production path:
`metadata enrichment request -> ResultRepository.updateDownloadItem -> fetchSingleMetadataFromSource -> matchesRequestedMetadataSource -> ExtractorSourceIdentityPolicy.matchesRequestedSource -> MediaPublishedDateSource.matches -> WebUrlInput source key -> applyMetadata -> durable consumer`.

The generic matcher accepts intersecting normalized source keys. `WebUrlInput.sourceKey()` and `sourceIdentityKey()` omit URI fragments. Thus a fresh candidate with the same scheme/host/path/query but a different fragment can be accepted as the requested source.

Concrete upstream-backed reproduction:
- requested A: `http://video.sina.com.cn/news/spj/topvideoes20160504/?opsubject_id=top1#250576622`;
- candidate B: same scheme/host/path/query but a different valid numeric fragment;
- exact yt-dlp `SinaIE` at `bbc809a1161d3bfca51fa36f59dda35556ee85a0` parses `#<digits>` as the media id, so A and B are distinct media identities;
- current generic app matcher can collapse them because its normalized keys omit the fragment;
- B may therefore contribute title/author/duration/thumb/date/etc. to Download A.

Affected files:
- `app/src/main/java/com/ireum/ytdl/database/repository/ResultRepository.kt`
- `app/src/main/java/com/ireum/ytdl/util/ExtractorSourceIdentity.kt`
- `app/src/main/java/com/ireum/ytdl/util/MediaPublishedDate.kt`
- `app/src/main/java/com/ireum/ytdl/util/WebUrlInput.kt`

- downstream durable metadata consumers and the new metadata identity test suite.
