### New confirmed P2 — provisional BUG-BACKUP-11

Title:
**Do not restore Terminal destination provider strings without restoring or validating provider authority**

Exact implementation SHA:
`cf7374510decad9f308fdc3f1b528e731a3ea4f1`

Severity:
**P2**

Violated invariant:
portable restore must not reconstruct executable external authority from a serialized locator alone when the destination installation has not independently established that authority.

Concrete production path:
1. `FolderSettingsFragment` selects Terminal `command_path` with `ACTION_OPEN_DOCUMENT_TREE`.
2. Normal configuration calls `takePersistableUriPermission` and stores the exact provider URI.
3. `BackupSettingsUtil.backupSettings()` serializes `command_path` because `isPortablePreferenceKey("command_path")` is true.
4. This differs from `cache_path`, which the same policy explicitly excludes as destination-local authority.
5. `BackupRestoreParser.normalize()` keeps imported `command_path`; `validateSettings()` validates type only.
6. Merge restore in `SettingsViewModel.restoreMergeData()` and reset restore in `RestoreTransactionCoordinator.publishPreferences()` commit the imported string.
7. Neither restore path repeats the Folder-picker authorization step nor proves a matching destination-side provider grant.
8. A later new Terminal enters `TerminalViewModel.insert()`.
9. `TerminalCommandIntentMaterializer` plus `TerminalDestinationAuthority.classify()` accept the syntactically valid provider URI and bind it into durable command/carrier/fingerprint identity.
10. `TerminalCommandPlanFactory` stages native output because provider authority is not a raw native path.
11. Provider usability is first discovered later at `FileUtil.resolveDestinationDocumentDir()` / publication.
12. The restore can therefore report success while future Terminal execution carries unproved destination authority and fails only after the setting has been accepted and the task has run into publication.

Affected files:
- `BackupSettingsUtil.kt`
- `BackupRestoreParser.kt`
- `SettingsViewModel.kt`
- `RestoreTransactionCoordinator.kt`
- `FolderSettingsFragment.kt`
- `TerminalViewModel.kt`
- `TerminalCommandIntentMaterializer.kt`
- `TerminalDestinationAuthority.kt`
- `TerminalCommandPlan.kt`
- `FileUtil.kt`

Disposition:
new confirmed P2. Pre-existing backup/settings portability root discovered by L6 DEEP. The current provider-binding change consumes and durably propagates the restored value but is not proven to have introduced the backup bug. Introducing commit: NOT_VERIFIED.

Distinct from:
- BUG-BACKUP-08: preference value-type support, not external authority portability.
- BUG-BACKUP-10: preference commit result propagation, not semantic validity of a successfully committed value.
- BUG-CACHE-02: cache-path native/provider contract; `cache_path` is already explicitly non-portable.
- BUG-TERMINAL-03: Terminal provider/raw authority and legacy Terminal intent; this new root begins at backup/restore authority reconstruction.

Required correction:
- preferably classify provider-backed `command_path` as destination-local and preserve the destination installation's current value during generic restore; require fresh Folder-picker authorization;
- alternatively restore it only as non-authoritative pending configuration and require independently verified destination-side grant before it can become executable authority.

Required focused regressions:
- imported provider command_path with no matching destination grant -> not executable after restore;
- destination already has valid B -> restore does not replace it with unproved A;
- explicit destination reauthorization of A -> later new Terminal can bind A;
- merge and reset restore;
- current-format active T1 keeps already-bound authority;
- legacy T1 control remains BUG-TERMINAL-03;
- raw/default path policy covered separately.
