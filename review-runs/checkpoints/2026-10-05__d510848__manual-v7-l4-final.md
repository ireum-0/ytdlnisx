## BUG-HISTORY-05 L4 deep trace

PlaylistItemCrossRef has composite primary key:
- playlistId
- historyItemId

Each row is durable set membership: one History item belongs to one Playlist.

Current deleteDuplicateHistoryGroups() correctly:
- normalizes candidate IDs;
- rereads exact current rows;
- recomputes HistoryDuplicateIdentity;
- retains earliest time/id;
- checks retained and duplicate identities before relationship work;
- transfers keyword assignments;
- materializes retained keywords;
- rechecks duplicate identity immediately before final History deletion.

But before that final History delete it currently calls:
deletePlaylistItemsByHistoryIds(listOf(duplicate.id))

without first materializing duplicate memberships onto retained.id.

Therefore:
- retained-only membership survives;
- shared retained+duplicate membership appears safe only because retained already owns it;
- duplicate-only membership is destroyed;
- multiple duplicates can each erase unique playlist memberships before their History rows are removed.

The current PlaylistDao already provides the complete narrow correction surface:
- getPlaylistItemsForHistory(historyItemId)
- insertPlaylistItems(items)
- deletePlaylistItemsByHistoryIds(ids)

insertPlaylistItems uses REPLACE and PlaylistItemCrossRef's composite PK makes repeated retargeting idempotently converge to a union.

Required in-transaction sequence remains:
1. after current duplicate identity proof, read duplicate's current playlist refs;
2. map each ref to retained.id;
3. insert/materialize those retained refs;
4. preserve existing assignment copy/materialization;
5. only then delete duplicate playlist refs and assignments;
6. preserve the final HISTORY-04 identity recheck;
7. delete duplicate History only after all relation/assignment work succeeds.

Across multiple duplicates the retained row must own the exact union across retained + every still-valid duplicate.

No schema/migration or new DAO method is required by current source.
