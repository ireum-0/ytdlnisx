## Confirmed open finding
### BUG-METADATA-02 / fragment-blind generic source relation
`ExtractorSourceIdentityPolicy.matchesRequestedSource()` accepts a generic trusted URL when `MediaPublishedDateSource.matches(requestedSource, candidateUrl)` succeeds. That matcher includes `WebUrlInput.sourceKey()` / `sourceIdentityKey()`, whose generic key intentionally omits URI fragment. Therefore URLs that differ only by fragment can compare equal.

Exact upstream counterexample: yt-dlp `SinaIE` at `bbc809a1161d3bfca51fa36f59dda35556ee85a0` has `_VALID_URL` extracting the media `id` from `#<digits>` and its test URL `http://video.sina.com.cn/news/spj/topvideoes20160504/?opsubject_id=top1#250576622` resolves id `250576622`.

Concrete semantic reproduction:
1. requested source A = `http://video.sina.com.cn/news/spj/topvideoes20160504/?opsubject_id=top1#250576622`;
2. fresh candidate provenance B uses the same scheme/host/path/query but a different valid `#<media-id>`;
3. A and B are distinct Sina media identities upstream;
4. current generic `MediaPublishedDateSource.matches(A, B)` can succeed because the comparison source key omits the fragment;
5. `fetchSingleMetadataFromSource(A)` therefore need not reject B;
6. FRESH_FIRST or CACHE_FIRST fresh fallback may apply B's metadata fields to Download A.

This violates Master Plan F13: unrelated fresh metadata contributes no field to a Download row.

## Why prior review missed it
Prior F13 reviews concentrated on the composition bypass: fresh candidates never reached the already-existing policy. The remediation correctly inserted that policy and added host/path mismatch, missing-provenance, YouTube-equivalence and Vimeo redirect tests. The review did not independently reopen the policy's generic URL equivalence semantics against extractor-specific identity-bearing URL components.

## Checklist gap
The v6 identity rule requires semantic granularity/provenance but the F13 execution coverage did not instantiate a generic provider whose identity is carried in a URI fragment. Reusing a previously accepted comparison helper was treated as sufficient once the bypass was fixed.

## Proposed checklist change

Any component removed by normalization must have provider-specific proof that it is non-identifying. Include at least one exact upstream fixture where a fragment is identity-bearing (currently SinaIE).
