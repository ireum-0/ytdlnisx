However semantic recovery is not closed. The only new production consumer of `collectRecovery()` is App startup logging; no path shown by this remediation consumes the recovery carrier to converge the Terminal durable result. In addition, after all output files have been published, `TerminalDownloadWorker` removes the artifact manifest, owner marker, and staging root before the later terminal DAO/log completion and before `terminalPublicationJournal.clear()`. A process death or ordinary post-publication failure in that window leaves the app-private COMPLETE publication journal as the surviving exact carrier, but `TerminalPublicationRecovery.reconcile()` rejects it because it requires the recorded source root to still be a directory with a valid live marker. The exact committed publication lineage is therefore not recoverable from every surviving durable carrier.
