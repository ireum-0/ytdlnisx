## Existing finding residual — BUG-CLEANUP-01 / F10
The new journal freezes the occurrence and DownloadItem targets before destructive work and no longer resets an arbitrary failed effect to ELIGIBLE. However, the effect journal advances `deletionCompleted` only after `deleteKnownUserRemovalExactTargets()` returns. Inside that helper, `deleteKnownUserRemoval()` performs Room deletion first, invokes `cleanupAfterRoomDeletionForTesting()`, and only afterward executes `deleteCache(authorizedItems)`. A process death/exception after Room deletion commits but before cache deletion/journal advancement leaves `deletionCompleted=false`. On retry, exact-target revalidation calls `getDownloadItemById()` and requires the row still to match the frozen operation/execution/start-time identity. The already-deleted rows therefore disappear from `authorizedItems`, so the retry can mark the deletion step complete without performing their remaining cache deletion. This is a confirmed distinct residual/subcase of the existing F10 root, not a new root.
