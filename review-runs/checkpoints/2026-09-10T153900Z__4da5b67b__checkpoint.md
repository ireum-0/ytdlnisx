## Open finding confirmed in this run

### `BUG-LINK-INPUT-01` — NEW P2 / OPEN

Invariant: every external text/share surface must establish one explicit input semantic class before durable Download admission. Supported addresses must normalize consistently, SearchQuery must use the product search route or be explicitly rejected on direct-download surfaces, and unsupported/malformed input must not silently become a runnable raw direct source.

Concrete path:

`ACTION_SEND text/plain` / `ACTION_VIEW`
→ `ShareActivity.handleIntents()`
→ `data.extractURL()`
→ `LinkUtil.extractFirstUrl()` returns `text.trim()` when no URL regex match exists
→ fallback `createEmptyResultItem(inputQuery)`
→ `createDownloadItemFromResult()` copies `resultItem.url` into a Queued Download
→ `queueDownloads()` durably persists queued input
→ ordinary yt-dlp request construction uses raw `downloadItem.url` rather than re-running `WebUrlInput.routeInput()`.

Concrete examples:

- `example.com/path`: normal input contract resolves it to extractor input with dispatch `https://example.com/path`; Share direct path preserves `example.com/path`.
- arbitrary text such as `best jazz live`: normal input contract classifies it as SearchQuery; Share direct path admits the raw text as Download source.
- `ftp://host/file`: `LinkUtil` extracts it, while `WebUrlInput` classifies FTP as unsupported for extractor dispatch; Share direct path can bypass that disposition.

Affected production files: `ShareActivity.kt`, `Extensions.kt`, `LinkUtil.kt`, `WebUrlInput.kt`, `DownloadViewModel.kt`, `YTDLPUtil.kt`, plus the exported Share manifest surface.

## Review retrospective

Structural miss: earlier reviews audited link normalization helpers and downstream identity/duplicate consumers, but did not require every external Android input surface to prove the same semantic route immediately before durable Download admission. `extractFirstUrl()` also obscures the gap by returning a plain String whose no-match value changes meaning from “no URL found” to “use all text as source.”

## Checklist gap

The v6 rules cover input normalization and authority strength, but the operational inventory did not force a surface-by-surface matrix through the durable admission boundary. A helper returning String also makes URL-found vs no-URL indistinguishable to callers.

## Proposed checklist change

For every external input producer, require a row:

`surface/action+MIME → raw payload → extraction result kind → normalized dispatch value → product route (extractor/search/reject) → durable carrier → native/remote consumer`.

Mandatory adversarial cases: plain HTTP(S), scheme-less supported address, arbitrary search text, unsupported explicit scheme, malformed/blank/null, surrounding prose, multiple URLs, and `onNewIntent` replacement. A rejected/direct-unsupported case must prove that no runnable durable Download is inserted; an accepted case must prove the exact normalized dispatch value persisted or otherwise carried into execution.
