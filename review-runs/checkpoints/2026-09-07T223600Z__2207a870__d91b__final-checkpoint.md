## Existing P2 — unchanged

A partial Terminal publication can leave exact current-attempt source files and an artifact manifest in the UUID-scoped staging directory. On failure, `cleanupTerminalOutputDirectory()` removes the owner marker with `revokeOwnershipPreservingArtifacts()` while retaining the manifest/files. This prevents a later attempt from inheriting publication authority, but it also removes the only admission proof accepted by `listOwnedRoots()`.

`TerminalCacheOwnership.listOwnedRoots()` returns only directories carrying a valid `.ytdlnisx-terminal-owner` marker. `CacheImportPlanner.collect()` obtains Terminal artifacts only from those owned roots, and `MoveCacheFilesWorker` consumes only the resulting planner manifest. Therefore the actual surviving post-failure state `artifact manifest + files + no owner marker` is filtered out before recovery/import mutation and remains physically preserved but production-undiscoverable after restart.

This continues to violate v6 core invariant 10 and the recovery-discovery/carrier-loss rule: recovery is not established if candidate construction filters out the surviving orphan/debt state.
