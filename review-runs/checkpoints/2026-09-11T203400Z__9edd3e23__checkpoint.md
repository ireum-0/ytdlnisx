### BUG-FORMAT-01
Re-traced current production path:
`UpdateMultipleDownloadsFormatsWorker -> ResultRepository.getFormats -> mutable Result/Download format state -> ResultDao.update -> reload current Download authority -> DownloadDao write -> per-item progress -> final WorkManager Result + notification`.

Confirmed source facts:
- entire per-item refresh sequence is wrapped in `runCatching` and the returned Kotlin `Result` is ignored;
- extraction, Result persistence, and Download persistence exceptions are therefore converted into continued iteration;
- `count` increments and progress publishes after the ignored failure;
- worker ultimately returns `Result.success()` unless a failure escapes outside the inner `runCatching`;
- Result update precedes Download update without a worker-level atomic transaction, so Result/Download split state is a real process/failure window;
- success-facing final notification is still emitted for the original ids when inner failures occur.

Provisional disposition: existing historical `BUG-FORMAT-01`, P2, OPEN / independently reproduced.
