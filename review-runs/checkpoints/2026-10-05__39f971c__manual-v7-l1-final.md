Current production can persist a malformed ytdlp_source even while desired_generation_domain is current. The important terminal cell is a valid custom source whose textual value equals a generic-valid non-String restore payload and whose destination generation is Long.MAX_VALUE.

Example source-semantic sequence:
1. destination has valid custom source "1", current generation-domain discriminator, generation Long.MAX_VALUE and matching proof;
2. Merge or Reset imports BackupSettingsItem(key="ytdlp_source", value="1", type="Int");
3. generic validation accepts Int "1";
4. reconcileRestoredSource() compares the payload string "1" to previous valid source "1" and classifies it as same source;
5. restoredSourceGeneration() therefore preserves Long.MAX_VALUE and no proof retirement occurs;
6. the editor then durably stores ytdlp_source as Int 1.

The resulting graph has:
- malformed ytdlp_source storage;
- current desired-generation-domain discriminator;
- Long.MAX_VALUE generation;
- potentially retained matching proof for the pre-restore source text.

UpdateUtil.readDesiredSourceLocked() reads source before generation. It cannot construct any authoritative DesiredSource from this malformed graph because getString() fails first.

Therefore this graph is NOT a genuine valid current-domain Long.MAX_VALUE identity. The generation number alone cannot require exhaustion preservation when the composite desired-source identity is invalid.

This resolves a conflict in the existing BUG-UPDATER-03 prompt. Recovery may perform a one-time canonical generation rebase for a malformed-source composite state, including the Long.MAX_VALUE cell, provided:
- recovery occurs before any typed consumer/request capture can accept a repaired identity;
- malformed source bytes are not coerced into user source intent;
- source recovers to the existing absence/default stable contract;
- source label is removed when necessary to avoid preserving a label for an unknowable malformed source;
- committed/pending proof is retired;
- failed publication remains untrusted and restart-safe;
- after recovery, the ordinary BUG-UPDATER-02 generation-domain contract resumes unchanged.

A valid source + current-domain Long.MAX_VALUE remains genuine exhaustion and must still fail closed on source change.

auto_update_ytdlp recovery has a separate default ambiguity:
- updating_preferences.xml declares default true;
- StartupYtdlpUpdateOwner reads absent key with getBoolean(..., false);
- App.setDefaultValues normally materializes XML defaults only when the spl gate runs.

Do not invent a Boolean from malformed bytes. The narrow source-supported fallback is key absence/removal, not an asserted true/false user choice. Runtime/UI behavior of absence must remain whatever existing product semantics already define.

ytdlp_source_label is non-authoritative display metadata. Wrong-type label recovery may use key absence rather than coercing bytes to text. If malformed ytdlp_source is recovered to default/absence, stale source-label metadata must not be retained as if it still identified the repaired source.

## Refined recovery contract

The persisted BUG-UPDATER-03 prompt remains the correct root/path but must be refined as follows.

1. Validity of desired source authority is composite:
   - source carrier must satisfy the String + nonblank contract;
   - desired-generation-domain must be current;
   - generation must satisfy the current numeric contract.
   A valid generation number alone does not make malformed source state authoritative.

2. For malformed ytdlp_source already persisted:
   - never coerce raw non-String/blank bytes into source intent;
   - recover to the existing absent/default source semantics;
   - remove stale source label when retaining it would falsely describe unknowable source intent;
   - retire committed/pending proof.

3. Generation handling for malformed source:
   - if the source carrier is invalid, the old generation is not a valid composite DesiredSource identity;
   - recovery may establish a safe canonical destination generation even when the numeric carrier is Long.MAX_VALUE;
   - this one-time rebase is allowed only for malformed-source recovery before normal typed consumers/request capture;
   - valid-source current-domain Long.MAX_VALUE remains exhausted and must not be reset.

4. Recovery publication must be durable and restart-safe:
   - failed commit/process-map publication remains untrusted;
   - restart must rediscover malformed state until the durable repair completes;
   - successful second run is idempotent.

5. auto_update_ytdlp:
   - do not coerce malformed bytes to Boolean;
   - use key absence/removal as the fail-safe representation unless exact implementation evidence proves a stronger already-established product contract;
   - do not claim the absent state semantically means a user-selected true or false beyond existing consumers/default machinery.

6. ytdlp_source_label:
   - do not coerce malformed bytes;
   - absence/removal is the safe representation;
   - source-label recovery alone must not alter source generation/proof.

7. Recovery timing:
   - StartupYtdlpUpdateOwner currently calls desiredSource() before awaitPrerequisites(), so recovery placed only in runtimeReadiness/initializeRuntime is too late for malformed source;
   - UI can also read label/source directly.
   The implementation must therefore establish a shared recovery authority or equivalent gating so no correctness-relevant typed consumer becomes the first unsafe reader.

8. Preserve BUG-UPDATER-02:
   - valid source/generation-domain states retain their accepted semantics;
   - no pre-domain generation trust is reintroduced;
   - valid current-domain Long.MAX_VALUE remains fail-closed;
   - source-changing recovery always invalidates stale proof/pending authority.
