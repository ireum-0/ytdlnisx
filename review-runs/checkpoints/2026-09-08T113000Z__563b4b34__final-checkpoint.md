## New P2 finding
### Provider creation UNKNOWN completion is incorrectly collapsed into FAILED/no-side-effect
Production paths:
1. MediaStore: persist reservation intent -> `ContentResolver.insert` -> provider crashes/remote call loses result -> framework returns null -> `FileUtil` invokes `onReservationFailed` -> journal `clearReservation` -> retry is allowed even though provider-side object creation is not proven absent.
2. SAF: persist reservation intent -> `DocumentsContract.createDocument` -> provider call throws/fails after uncertain completion -> framework helper returns null -> `FileUtil` invokes `onReservationFailed` -> same authority loss.
3. Process death after provider object creation but before returned URI reaches `reserve()` leaves only the opaque intent. Current Download and Terminal recovery intentionally block unresolved intents, but there is no production mechanism to discover the exact created provider object, prove rollback, or converge the obligation.

Impact:
- In the null/crash branch, a later collision-safe retry may create a second output because the only durable fence was cleared without proof that the first provider mutation did not occur.
- In the process-death branch, the fence prevents duplication but can remain permanently non-convergent because it contains no exact provider URI and no reconciliation locator.

Disposition: NEW P2 blocker, in-scope under existing `BUG-OUTPUT-01`; ledger closure not permitted.

## Review retrospective / checklist gap
The remediation correctly added a pre-call intent but modeled provider completion as binary: exact URI returned vs failure. The actual external API has a third state: UNKNOWN completion. Previous review focused on the create/return crash window and duplicate fencing, but did not force the null/RemoteException/provider-crash semantic through the same three-state completion model and recovery-convergence proof.

Proposed checklist change: for every external create/insert API that allocates an opaque identity, require an explicit completion trichotomy: `PROVEN_NOT_CREATED`, `CREATED_WITH_EXACT_ID`, `UNKNOWN`. Generic exception/null/provider death must remain `UNKNOWN` unless upstream guarantees rollback/no-side-effect. UNKNOWN may not clear durable intent; recovery must have an exact discovery/rollback/convergence protocol or remain an explicit blocker.
