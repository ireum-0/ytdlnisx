### Existing confirmed P2 — provisional BUG-BACKUP-11 remains confirmed

Title:
**Do not restore Terminal destination provider strings without restoring or validating provider authority**

Exact implementation SHA:

#### Platform contract

Normal configuration path:
1. `FolderSettingsFragment` launches `ACTION_OPEN_DOCUMENT_TREE`.
2. It requests READ, WRITE, and PERSISTABLE URI flags.
3. On success it calls `takePersistableUriPermission(... READ|WRITE)`.
4. It stores the exact returned URI in SharedPreferences `command_path`.

Backup representation:
1. `BackupSettingsUtil.backupSettings()` serializes portable preference key/type/value.
2. `cache_path` is explicitly excluded as destination-local.
3. `command_path` is not excluded.
4. The backup schema contains the URI locator string but no destination-install grant/provenance dimension.

Restore:
1. `BackupRestoreParser.normalize()` retains `command_path`.
2. `validateSettings()` validates the SharedPreferences value type, not provider authorization.
3. Merge restore writes the string through `SettingsViewModel.restoreMergeData()`.
4. Reset restore writes portable settings through `RestoreTransactionCoordinator.publishPreferences()`.
5. Neither restore path re-performs `takePersistableUriPermission`.
6. Neither path requires a matching destination-side persisted URI permission before reporting restore success.

Terminal execution:
1. `TerminalViewModel.insert()` reads the restored `command_path`.
2. `TerminalCommandIntentMaterializer` calls the typed destination logic.
3. `TerminalDestinationAuthority.classify()` accepts a nonblank `content://<authority>/...` value as ProviderTree based on representation.
4. The URI is then embedded into durable Terminal command/carrier/fingerprint identity.
5. Real provider usability is deferred to later DocumentFile/FileUtil publication.

Therefore the normal settings UI establishes two dimensions:
- locator
- provider authorization

but backup/restore serializes/reconstructs only the locator while treating the result as portable executable configuration.

This violates v6 Module C: syntactic representation is not proof of semantic authority preservation.

#### Test/verification gap

`TerminalSafDestinationAuthorityProductionWiringTest` puts provider URI strings directly into SharedPreferences and verifies planning/identity. It does not establish a real persisted URI grant.

Current backup settings tests prove `cache_path` is non-portable but do not cover provider-backed `command_path`.

No focused production-wiring regression was found for:
backup -> restore on destination without grant -> new Terminal -> provider publication.

Required correction remains:
- preferably treat provider-backed `command_path` as destination-local and preserve/reselect destination authority;
- or restore it only as non-authoritative pending configuration and require independent destination authorization before it can become executable.
