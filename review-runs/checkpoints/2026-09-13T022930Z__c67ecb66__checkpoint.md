### BUG-CLEANUP-01 — EXISTING / P2 / OPEN

Substantial source progress is confirmed:
- stable unique-work identity exists;
- success publishes one calendar successor;
- transient retry does not duplicate successor work;
- persisted generation/cadence fences stale successor publication;
- disable/change cancels old tagged work and installs new authority first;
- startup reconciliation repairs a missing/finished/stale chain;
- monthly schedules preserve their original anchor day.

Residual correctness failure:
- cleanup failure returns `Result.retry()` only while `runAttemptCount < MAX_ATTEMPTS - 1`;
- on the final allowed attempt it returns `Result.failure()` before `scheduleSuccessor()`;
- WorkManager failure terminates the occurrence/chain and no successor has been enqueued;
- the persisted daily/weekly/monthly preference remains enabled;
- `CleanupScheduleCoordinator.reconcile()` is only called on app startup (apart from direct test/use entry), so if the process remains alive after the final failure, no future occurrence is scheduled.

Concrete reproduction:
1. Configure daily/weekly/monthly cleanup.
2. Force the cleanup side effect to throw for all three attempts.
3. Attempts 0 and 1 return retry.
4. Attempt 2 returns failure before successor publication.
5. Keep the process alive; there is no periodic reconciler or failure-path successor publication.
6. The UI/persisted cadence remains enabled while automatic cleanup no longer recurs.

## Exact upstream semantic basis

- Android Developers WorkManager chain semantics: dependents proceed after `Result.success()`; a `Result.failure()` marks dependent work failed; retry retries the same request.
- AndroidX `ExistingWorkPolicy.APPEND_OR_REPLACE`: append to existing unfinished leaves; failed/cancelled prerequisites are dropped only when a new append operation is issued.
- Android Developers WorkManager cancellation: cancellation is best-effort and already-running work may continue; cancellation request return is not a synchronous semantic barrier.
- Android Developers `CoroutineWorker`: stopped worker future is cancelled and its result is ignored.
