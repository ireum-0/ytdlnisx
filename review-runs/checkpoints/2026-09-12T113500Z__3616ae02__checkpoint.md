1. History H has MANUAL assignment plus RULE A derived assignment.
2. Delete captures the assignment snapshot.
3. Before Undo, A remains in the rule table but current semantics change so H is no longer currently entitled to A (for example disable/revision/current eligible-match change), and/or a currently applicable RULE B becomes authoritative.
4. Undo calls `restoreHistory(item, snapshot)`.
5. The restore transaction filters snapshotted RULE rows only by whether `dao.getRule(ruleId)` still returns a row, then reinserts them and materializes keywords.
