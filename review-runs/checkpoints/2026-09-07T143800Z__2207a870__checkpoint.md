## Status change from previous review

The previous Download-cache ownership-bootstrap P0 is source-level FIXED at this checkpoint.

`DownloadCacheOwnership.ensureMarker()` refuses to bootstrap ownership over a pre-existing nonempty numeric root, and the exact artifact manifest is now bound to downloadId + operationId + executionId before it can authorize cleanup/import. The previous `new marker -> old manifest -> delete old files` path is therefore closed in current source.

## Existing P2 remains open — Terminal partial-publication recovery is not discoverable

The previous direct destructive cleanup has been improved: Terminal failure cleanup no longer recursively deletes a partial-publication remainder. `cleanupTerminalOutputDirectory()` calls `TerminalCacheOwnership.revokeOwnershipPreservingArtifacts()`, which removes the exact ownership marker and retains the artifact manifest/files.

However, the surviving state is not production-discoverable:

1. `revokeOwnershipPreservingArtifacts()` removes `.ytdlnisx-terminal-owner` while keeping the manifest/files.
2. `TerminalCacheOwnership.listOwnedRoots()` constructs candidates only from Terminal directories that still contain a valid owner marker.
3. `CacheImportPlanner.collect()` obtains Terminal recovery/import candidates exclusively through `TerminalCacheOwnership.listOwnedRoots()` and then reads manifests from those marker-backed roots.
4. Therefore the exact state created by partial-publication failure — manifest/files present, marker absent — is filtered out before reconciliation/import candidate construction.
5. The worker also deletes the Terminal DAO row on ordinary failure, so the reviewed path does not retain another visible task carrier that points back to this exact staging directory.

Physical preservation alone is not recovery. The preserved exact remainder is orphaned from the production recovery discovery graph.

This violates v6 core invariant 10: recovery must be discoverable from every surviving durable carrier; reconciliation code is insufficient if candidate construction filters out the orphan/debt state.

Disposition: existing P2 remains OPEN in changed failure form. This is not a new canonical finding.

## Checklist evolution

Proposed operational addition to v6:

`Quarantine / authority-revocation recovery row`

Whenever remediation revokes/deletes an ownership marker, lease, live token, or other authority carrier while retaining artifacts:

1. enumerate the exact surviving durable carriers;
2. enumerate every production recovery/reconcile candidate constructor;
3. prove at least one constructor selects the marker-revoked/quarantined state;
4. prove the surviving carrier preserves enough exact provenance to authorize only recovery, not ordinary publication/destruction;
5. test process death/restart after revocation and before recovery;
6. do not count physical artifact survival as recovery evidence by itself.
