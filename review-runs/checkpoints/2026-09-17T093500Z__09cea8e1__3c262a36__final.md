Android WorkManager's current long-running-worker contract provides suspending `CoroutineWorker.setForeground()` as the Kotlin completion-aware form. Disposition: existing root OPEN; newly recorded residual/subcase, not a new canonical finding.

### Existing `BULK-FORMAT-SILENT-PARTIAL-SUCCESS-01` — P2 OPEN
L3 DEEP confirmed a concurrency/authority subcase: the worker reads the current Download row/executionId, then invokes transactional `updateIfExecutionOwned(d, current.executionId)`. The DAO revalidates exact execution ownership and returns Boolean false if authority changed, but the worker ignores that Boolean inside `runCatching`. Therefore a concurrent supersession/CAS rejection is converted into `count++`, progress publication, aggregate `Result.success()`, and final bundle-complete notification. Room's transaction contract makes the DAO revalidation atomic with its transaction; the defect is the caller's ignored negative authority result. Disposition: existing root OPEN; distinct residual/subcase, not a new canonical finding.
