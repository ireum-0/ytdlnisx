## Open candidates / questions
- Cross-representation identity is not closed: when tree metadata is present, `identityForUri()` returns only `tree:<normalized-tree>|<relative-path>` and suppresses the provider-level `authority + documentId` identity. The same DocumentsProvider object may be represented by a direct document URI (`buildDocumentUri`) or a tree-backed document URI (`buildDocumentUriUsingTree`) with the same authority/document ID. Existing History inserted through the direct form can therefore expose `provider:<authority>:<documentId>`, while the same object added through a tree exposes only the tree identity; exact URI strings also differ, so worker/UI prechecks need not catch it.
- Current regression tests cover provider identity, tree identity, filename collision, and concurrent identical admission separately, but not direct-document-vs-tree-backed representation of the same provider document.

## Concrete reproduction candidate
1. Insert History for direct document URI built from authority `provider` and document ID `root/child`, with no `localTreeUri/localTreePath`.
2. Later LocalAdd the same provider document through a granted tree URI for `root`, producing a tree-backed document URI for document ID `root/child` and storing tree metadata (`root`, relative `child`).
3. First History identity set contains `provider:provider:root/child`; second contains only `tree:<tree-uri>|child` because tree identity returns early.
4. URL can differ/unknown for manual LocalAdd, and direct/tree-backed URI strings differ.
5. Final admission therefore can insert the same storage object twice.

## Exact upstream semantic basis
- Android `DocumentsContract`: `buildDocumentUri(authority, documentId)` and `buildDocumentUriUsingTree(treeUri, documentId)` both represent the target `Document.COLUMN_DOCUMENT_ID`; the tree-backed form differs by leveraging subtree access. `getDocumentId()` extracts that document ID. This supports treating authority + document ID as a cross-representation identity for a DocumentsProvider object rather than treating the tree URI form as a separate storage object.
