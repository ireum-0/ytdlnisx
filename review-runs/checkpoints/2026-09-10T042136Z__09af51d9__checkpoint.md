### Confirmed candidate: BUG-TERMINAL-HANDOFF-01, provisional P2

Production `TerminalViewModel.startTerminalDownloadWorker()` constructs a one-time request and calls `beginUniqueWork(...).enqueue()` without awaiting/observing the returned WorkManager `Operation`. The durable Terminal row is created before this call. Thus `Terminal row commit -> process death/enqueue failure before accepted WorkManager ownership -> no worker admission/execution witness` is a surviving-carrier gap. Existing Terminal execution recovery begins only after worker admission and does not itself make the pre-enqueue Room row an accepted scheduler carrier.

### Confirmed candidate: BUG-LOCALADD-HANDOFF-01, provisional P2

Thus `entries durable -> process death/enqueue failure before accepted WorkManager ownership` can strand durable input with no recovery owner.
