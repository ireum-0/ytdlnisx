## Finding disposition

### BUG-DUPLICATE-ADMISSION-01 — EXISTING / P2 / OPEN / CONFIRMED

The original check-then-separate-insert duplicate race is fixed at the repository transaction boundary, but the Observe consumer/effect graph remains incorrect:

1. `insertNewWithDuplicateAdmission` commits a new Queued row.
2. Observe writes the returned id into its existing pre-claim in-memory item.
3. Download worker claim can win after commit and change the durable row to `Active` with a fresh `executionId`.
4. Observe then reaches its generic `id > 0 && status == Queued` branch and calls `downloadRepo.update(it)` on the stale producer snapshot.
5. DAO `update()` is not execution-owner CAS and, absent unrelated barrier/debt guards, calls `@Upsert updateRaw(item)`.
6. Room Upsert updates the existing primary-key row from the supplied entity, so the stale producer can erase the newer Active/executionId worker claim.

Violated invariants: positive live authority; discovery/candidate is not mutation authority; material semantic-contract consumer closure and authority-effect closure; exact ownership at the final durable mutation boundary.

Affected files: `ObserveSourceWorker.kt`, `DownloadRepository.kt`, `DownloadDao.kt`, worker claim/admission path, `DownloadDuplicateAdmissionProductionWiringTest.kt`.

The added instrumentation proves duplicate decision/insertion serialization but does not force `Observe insert commit -> worker claim -> Observe producer continuation`, so it does not close the remaining ownership race.
