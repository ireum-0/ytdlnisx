## New finding candidate confirmed

### HISTORY-CONTENT-AUTHORITY-ALIAS-01 — NEW / P2 / OPEN

`HistoryDeletionTargetParser.parseContentUri()` forms a document deletion identity from `${uri.authority.lowercase(Locale.US)}:$documentId`. Android/AOSP ContentProvider authority validation uses exact Java `String.equals`, so lowercasing widens platform provider identity.

Concrete source reproduction:

1. Two valid content document targets differ only in provider authority case but share document ID, for example `content://ProviderA/document/42` and `content://providera/document/42`.
2. The parser lowers both authorities and hashes the same `content-document` value, producing the same target key/reference key despite platform-exact provider authority being distinct.
3. `HistoryFileDeletionEngine.validate()` canonicalizes targets that share a reference key to one canonical target and assigns that same canonical key to both records.
4. `execute()` invokes gateway deletion only once for the canonical target. If that deletion returns DELETED/ALREADY_ABSENT, both records' key sets satisfy `allowsRecordRemoval` and both record IDs become removable, even though the second provider/document target was never independently deleted/proven absent.
5. Production History/Observe consumers use `removableRecordIds` to delete History records, so a selected record can lose its durable History identity while its distinct associated file remains.

Violated invariant: Master Plan/v6 destructive identity must preserve semantic granularity/provenance; grouping/deduplication keys that authorize durable mutation may not widen exact identity. v6 core invariant 12 and identity/equality rules directly apply.

Affected production files: `app/src/main/java/com/ireum/ytdl/util/storage/HistoryFileDeletion.kt`; downstream consumers include `HistoryViewModel.kt` and Observe History deletion in `ObserveSourceWorker.kt`.

Disposition: source-confirmed NEW P2 OPEN. Runtime/device reproduction NOT_VERIFIED.

Why previous reviews missed it: F20 reviews correctly fixed provider-authority normalization in LocalAdd, but review scope followed the LocalAdd producer/admission graph and did not propagate the newly established exact-authority semantic basis to a repository-wide search of other identity keys used by destructive/reference cleanup. The History deletion parser remained outside that feature-local trace despite performing the same unsafe authority normalization.

Checklist gap: v6 already requires exact identity/provenance and collision construction, but does not explicitly require repository-wide propagation when a review establishes that a normalization/equality transformation is invalid under upstream namespace semantics.

Proposed checklist change: when any finding establishes an unsafe identity transformation (case-folding, trimming, prefix/substring/path reinterpretation, basename/title collapse, partial tuple, etc.), require a targeted repository-wide search for the same transformation at every destructive, deduplication, retained-reference, cleanup, admission, and recovery key; each hit must be classified against its upstream namespace equality before closing the review.
