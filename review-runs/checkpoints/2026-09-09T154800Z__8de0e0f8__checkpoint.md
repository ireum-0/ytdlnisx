## NEW F19 evidence

Production reproduction A (manual active/queued):
1. `prevent_duplicate_downloads = config`.
2. Existing active/queued item uses supported URL form A and configuration C.
3. User queues equivalent supported URL form B for the same media ID with configuration C.
4. `DownloadBottomSheetDialog -> DownloadViewModel.queueDownloads -> detectAndMarkDuplicates -> DownloadConfigurationDuplicatePolicy.findMatch` compares raw URL as part of full configuration.
5. A != B, so no config duplicate is found and the equivalent media can be queued again.

Production reproduction B (manual History):
1. Existing History output for form A exists.
2. User queues form B with command-equivalent configuration.
3. Config branch computes `canonicalHistory` from equivalent forms but the actual `existingHistoryItem` predicate reads only exact-URL `history`.
4. The canonical candidate is therefore not used by the decision and the duplicate is missed.

Observe config-mode active/queued matching delegates to the same raw-URL configuration policy; Observe History is already canonicalized, showing partial consumer propagation rather than closure.

## Proposed checklist change

For duplicate/dedup identity reviews, require a matrix:
- mode: `download_archive`, `url_type`, `config`
- ingress: manual/single, multi/batch, History-derived, Observe
- comparison sink: batch-local, active/queued, History

For each supported canonical-media provider, feed equivalent URL forms representing the same media ID and prove that the canonical media identity is the source-identity component of the *actual predicate*, while meaningful format/path/subtitle/config fields remain independent. Add an explicit rule: computing or logging a canonical candidate set does not establish closure unless that set feeds the final equality/selection decision.
